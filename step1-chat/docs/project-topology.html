6i.1 六个设计决策（后面所有实现都由它们推导）

决策内容为什么
D1 公共接入层四条链路只允许依赖 memory/bridge.ts，不许直接调 memory/retrieve.ts / memory/pipeline.ts阈值、Top-5、预算裁剪、「资料不是指令」的口径全部收敛在一处，是「行为不漂移」的唯一保障
D2 记忆是数据不是指令multi 用独立 system 消息；plan / rag / structured 用追加小节，小节标题统一 ## 用户长期记忆「记住某句话」不能变成系统命令；小节措辞逐字一致才叫同一套能力
D3 检索只做一次检索放在路由层，检索一次，同一块 memoryBlock 下传给全链路multi 有 4 个 worker——各检索一次就是一次请求 4 次向量检索，而且同一轮注入两份不同记忆会让模型困惑
D4 抽取输入按链路裁剪公共口径 buildExtractionInput：只取最近 N 轮用户消息 + 可选最终回复喂得越杂记忆越脏；工具返回、检索片段、模型自己的输出都不是用户事实
D5 失败即旁路检索 / 抽取 / 落盘任一步失败 → 只发 memory_failed，本轮回复照常记忆是增强项，不能成为可用性风险
D6 前端契约统一请求体统一 userId + allowMemory；关掉时连 userId 一起不带；事件统一走 api/memoryTrace.ts 解析服务端要求 allowMemory===true 且 userId 合法才检索——前端不带，零检索零抽取才是真的关掉

6i.6 失败边界

场景行为
检索失败（向量服务不可用）本轮不注入，发 memory_failed(stage=retrieve)，回复照常
抽取失败（模型超时 / 非法 JSON）本轮不存，发 memory_failed(stage=extract)，回复照常
落盘失败发 memory_failed(stage=store)，回复照常
用户关闭开关五条链路一律零检索、零抽取
userId 非法（不匹配 anon_*）服务端按「无记忆」处理，不报错
记忆块过长沿用 Top-5 上限 + 200 token / 10% 预算裁剪，不引入新的裁剪机制
structured 的记忆含非法 JSON 字符记忆块不进 JSON 输出路径，只进 system prompt

6i.7 隐私红线（五条链路共同遵守）

  • 记忆只进 system prompt / 用户事实小节，永远不进「引用来源」「资料编号」体系。
  • 抽取输入永远排除检索片段、工具返回、结构化输出内容。
  • 记忆内容不写进日志正文——只记 id、条数、token 估算，与现有 trace 口径一致。
  • 阶段 8 的两道敏感信息闸（送模型前脱敏、模型输出后拦一次）本阶段复用未改。
  • 冲突仍不自动覆盖，交给用户在面板裁决。
