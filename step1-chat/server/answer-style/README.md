# server/answer-style/ — 知识库回答风格收敛

## 模块职责

模型看过检索到的原文之后，很容易把「检索结果」原样打印出来：正文后面挂一段 `来源:`，
正文里混进 `id= / source= / title=` 这些内部字段。这个模块把这些痕迹洗掉，
让输出读起来像**答案**，而不是「检索结果打印」。

适用两条链路：

1. `POST /api/chat` 勾选「搜索知识库」后的本轮回答
2. `POST /api/rag/chat` 资料问答回答

## 文件说明

| 文件 | 职责 |
| --- | --- |
| `knowledgeAnswer.ts` | `normalizeKnowledgeAnswer()`：清理检索元信息与多余空行 |

## 它做什么、不做什么

**做**：

- 删掉尾部单独成段的 `来源:` / `来源：` 区块
- 删掉正文里单独的 `id=` / `source=` / `title=` 内部字段行
- 连续 3 个以上空行压成 2 个
- 保留正文里的 `[1][2]` 行内引用

**不做**：

- 不改写句子，不「优化表达」
- 不动 `[n]` 引用编号
- 不判断引用是否真的对应上了某条命中

## 为什么是「保守删除」而不是「重写」

清洗器一旦开始改写句子，就会引入新的不确定性：改写可能改变事实、
可能吞掉引用。这里只做能被规则精确判定的删除，代价是**改不掉语序别扭的句子**，
好处是**永远不会把内容改错**。

如果将来产品要求「展示完整来源清单」，正确的做法是给清洗器加一个开关跳过，
而不是在清洗器里加分支——那属于两种不同的产品形态。
