两套 Trace 为何必须分开

SSE onTrace vs LangSmith
  1. SSE：产品体验。用户看 tool_call、点确认、看 injection。关 LangSmith 也必须能用。
  2. LangSmith：开发者 span 树、耗时、排错。需要 API Key，默认关；打开也不应把内部 span 细节推给用户面板。
业务节点 → onTrace/writeSse → ToolTracePanel 业务节点 → traceable(...) → LangSmith 云端（可选）
混成一套会导致：要么关掉云端后面板也死，要么把开发者细节塞给用户。分开才能独立开关。

Token：为何是「请求级累加」

UsageAccumulator 心智模型
  1. 用户点一次发送 = 一次 HTTP 请求 = 一个 Accumulator 实例。
  2. 该请求内每次 LLM HTTP 成功解析 usage → record(model, source, usage)。
  3. 请求结束 toRecord 落盘 + SSE type:usage；Mock/判空无调用则 isEmpty，不写。
若按「一条气泡一次 Token」记账，ReAct 3 次 askModel 会被严重低估。详见 usage.html。

Guard 时序（三道门）

用户文本 → inputGuard（标记）→ 业务/LLM →（有 tools）toolGuard → [可选 confirm] → 执行 → 最终文本 → outputGuard（可替换）→ 出站

细节步骤见 guard.html。人工确认在 toolGuard 通过之后：先证明参数合法，再等人放行。
