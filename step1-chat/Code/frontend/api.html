04 · 前端 API src/api/

浏览器侧 HTTP / SSE 客户端层：只负责拼请求、读流、按事件类型回调。 不持有 Vue 状态——messages / Trace / Usage 全由 useChat 注入的回调写入。 三个文件对应三条能力：普通对话（含确认/健康检查）、资料问答、用量汇总。

src/api/chat.ts

类型：StreamChatParams、HealthInfo、ConfirmChatParams。导出 confirmChatTool、streamChat、fetchHealth。

StreamChatParams（接口）
interface StreamChatParams { messages; model; signal; searchDocs?; multiAgent?; onDelta; onTrace?; onUsage?; onError }

做什么：约定 streamChat 的入参形状。消息只带 role/content（不含前端 id / rag 字段）；回调把解析结果回灌给 composable。

字段类型含义
messages{role, content}[]发给服务端的对话上下文
modelstring模型 id
signalAbortSignalstop() 中止同源
searchDocsboolean?是否打开知识库检索（只进 body）
multiAgentboolean?选路：true→multi，false→单 Agent；默认 true
onDelta / onTrace / onUsage / onError回调正文 / 过程 / Token / 错误
把「选路」和「是否搜索」拆成两个字段，避免隐式耦合；回调可选（onTrace/onUsage），让单元测试或精简调用方不必全填。
confirmChatTool
async function confirmChatTool(params: ConfirmChatParams): Promise<void>

做什么：向服务端提交人工确认结果（允许或拒绝某次 tool_call）。只通知 ConfirmSession.resolve；不执行工具、不拉新聊天流。单 Agent 与多 Agent 共用同一确认端点。

  1. POST /api/chat/confirm，JSON body 为 confirmId / toolCallId / action。
  2. 若 !response.ok，尝试解析 body.error，否则用状态码拼错误信息并 throw。
  3. 成功则静默返回（后续事件仍走原聊天 SSE）。
方向名称说明
入参confirmId服务端确认会话 id
入参toolCallId待确认工具调用 id
入参action"allow" | "deny"
出参—成功 void；失败抛 Error
上下游：resolveToolConfirm 调用本函数。服务端解开 applyToolCalls / multi 路径里的 await wait。
确认必须是短 JSON 请求：原聊天 SSE 连接正阻塞在 wait 上，无法再往同一 body 塞确认。分连接是正确模型。
streamChat
async function streamChat(params: StreamChatParams): Promise<boolean>

做什么：普通对话的 SSE 客户端。按 multiAgent 选择 endpoint，POST 消息后用 ReadableStream 按「空行分隔事件」解析 data: 行，分发到各类回调。返回值表示「流是否正常结束」（含收到业务 error 事件后的收尾），abort 时返回 false。

  1. endpoint = multiAgent ? "/api/chat/multi" : "/api/chat"；默认 multiAgent=true。
  2. fetch POST：body 含 messages、model、searchDocs: Boolean(searchDocs)；带 signal。
  3. 网络异常：若已 abort 返回 false；否则 onError 后返回 false。
  4. 非 ok 或无 body：onError 相应文案，返回 false。
  5. 循环 reader.read：解码进 buffer，按 \n\n 切事件；对每行 data:：
    • [DONE] → return true。
    • JSON error → onError，return true（业务错误也算「流走完」）。
    • type==="usage" → onUsage 组装 UsageSnapshot。
    • tool_call / tool_result → onTrace。
    • injection_detected / output_leak_blocked → onTrace（Guard 可视化）。
    • pending_confirm → onTrace（status=pending）。
    • confirm_resolved → onTrace（allow/deny）。
    • 有 delta → onDelta。
    • JSON 解析失败则忽略该片（中间残片容错）。
  6. 读流异常：abort 则 false，否则 onError 后 false；自然读完返回 true。
方向名称说明
入参见 StreamChatParams含回调
出参booleantrue=正常结束或业务 error 已回调；false=中止或传输失败
上下游：useChat.runStream → 本函数 → 服务端 chat / chatMulti。返回值给 runSseSession 决定是否填空泡兜底文案。
SSE 解析集中在 api 层，composable 只关心语义回调；endpoint 与 searchDocs 解耦写在客户端显式字段上，避免隐式「有工具就走 multi」。
fetchHealth
async function fetchHealth(): Promise<HealthInfo | null>

做什么：探测后端是否可用以及当前是 mock 还是真实 API 模式，供顶栏提示。

  1. GET /api/health。
  2. 非 ok 或网络失败返回 null（调用方显示 unknown）。
  3. 成功则 JSON 断言为 { mode: "mock"|"api", model: string }。
上下游：useChat.onMounted。失败不抛错，避免启动时顶栏红屏。
健康检查应「软失败」：后端没起来时聊天页仍能打开，只是 mode=unknown，方便本地教学排错。

src/api/rag.ts

AskRagParams（接口）
interface AskRagParams { question; history; model; signal; onDelta; onTrace?; onUsage?; onRagMeta?; onError }

做什么：约定资料问答请求。注意 history 必须是「当前问题之前」的对话，不要把当前 question 再塞进去——服务端会自己拼最后一条 user。

字段说明
question当前用户问句
historyprior 轮次；role/content only
onRagMeta收到 rag_meta 时写入命中面板元数据
其余回调与 streamChat 同形态
question 与 history 拆开，和后端 buildRagPrompt 契约对齐；重复问句是常见 bug，类型注释里写死提醒。
parseHits（内部）
function parseHits(raw: unknown): RagHitView[]

做什么：把 SSE rag_meta 里的 hits 数组清洗成前端 RagHitView 列表。非法元素跳过，缺省字段补默认值，避免坏数据打崩命中面板。

  1. 非数组 → 返回 []。
  2. 逐项检查：必须是对象，且 id:string、text:string、score:number，否则 continue。
  3. 补齐 rank（缺省用当前长度+1）、rerankRank/promptIndex（缺省 null）、source/title（缺省空串）、rerankScore（缺省 null）。
方向名称说明
入参raw事件里的 hits 任意 JSON
出参RagHitView[]仅合法命中
上下游：仅 askRag 在 type==="rag_meta" 时调用。
服务端字段可能演进；防御式解析比「整包 any 丢给 Vue」更稳，也避免一次脏数据拖垮整个 Trace/Hits UI。
askRag
async function askRag(params: AskRagParams): Promise<boolean>

做什么：资料问答 SSE 客户端。POST /api/rag/chat，解析事件序列与 streamChat 同形态（过程事件 + delta + usage），额外支持 rag_meta（命中列表、是否调模型、是否空检索等）。

  1. fetch POST body：{ question, history, model }，带 signal。
  2. 错误处理与 streamChat 对称：网络/HTTP/无 body → onError + false；abort → false。
  3. SSE 循环：遇 [DONE] 返回 true；error 字段 onError 后 true。
  4. usage / tool_call / tool_result / injection_detected / output_leak_blocked → 对应 onUsage / onTrace。
  5. type==="rag_meta" → onRagMeta（empty、calledModel、topScore、question、hits=parseHits、以及可选 leak/toolGuard 标记）。
  6. 有 delta → onDelta。解析失败忽略残片。
方向名称说明
出参boolean语义同 streamChat：正常结束 true，中止/传输失败 false
上下游：useChat.runRag → 本函数 → ragChat 路由。典型事件序：injection? → tool_* → output_leak? → rag_meta → delta* → usage? → [DONE]。
RAG 曾返回整包 JSON；改成 SSE 后才能把 tool_call / Guard 事件推到 ToolTracePanel，与 chat 学习路径对齐，也支持答案流式打字。

src/api/usage.ts

fetchUsageSummary
async function fetchUsageSummary(): Promise<UsageSummary | null>

做什么：拉取服务端全局 Token / 成本汇总（含 byEndpoint、byModel、recent），给 UsagePanel「累计」区块。

  1. GET /api/usage。
  2. 非 ok 或异常返回 null（面板显示空态）。
  3. 成功则断言为 UsageSummary。
上下游：useChat.refreshUsageSummary；服务端 getUsageSummary。
汇总落在服务端 store（可跨刷新）；单次请求用量仍走当次 SSE，减少轮询。软失败避免汇总挂了拖垮整页。
clearUsageHistory
async function clearUsageHistory(): Promise<boolean>

做什么：清空服务端用量日志（学习 demo 用），返回是否成功。

  1. DELETE /api/usage。
  2. 返回 response.ok；网络异常返回 false。
上下游：UsagePanel「清空」按钮；服务端 clearUsageRecords。
demo 环境允许一键清账，方便反复跑同一场景对比成本；生产应换成权限控制与软删除。
