export function setSseHeaders(res: express.Response): void

  2. Cache-Control: no-cache, no-transform
  3. Connection: keep-alive
  4. X-Accel-Buffering: no（关反向代理缓冲，保证块及时到浏览器）

writeUsageToStream
export function writeUsageToStream(res, accumulator, endpoint, defaultModel): void
  1. 若 accumulator.isEmpty 或响应已结束 → 直接 return（Mock / 检索判空未调 LLM）。
  2. accumulator.toRecord(endpoint, defaultModel) 合成 UsageRecord。
  3. appendUsageRecord 落盘。
  4. SSE 推 { type:"usage", ...record }。
参数说明
resSSE 响应
accumulator本请求的 Token 累加器
endpoint"chat" | "chat/multi" | "rag/chat" 等
defaultModel记录用模型名

上游：三条聊天 SSE 在 [DONE] 前 · 下游：usage store + 前端 UsagePanel

落盘与推流绑在同一函数，保证「面板看到的累计」与文件一致；空累加跳过避免假 0 usage 噪声。

chat.ts · POST /api/chat

registerChatRoutes
export function registerChatRoutes(app: Express): void
  1. setSseHeaders(res)。
  2. 校验 messages 为数组；否则 SSE error 并 end。
  3. AbortController：res.on("close") 时 abort（中止 LLM / 确认 wait）。
  4. new ConfirmSession() 登记到全局 Map（供 confirm 路由）。
  5. UsageAccumulator + bindUsageCallback(..., "askModel")。
  6. createChatStream：onDelta → {delta}；onTrace → 原样 SSE（tool/confirm/injection…）。
  7. writeUsageToStream(..., "chat") → data: [DONE] → end。
  8. catch 写 error；finally confirmSession.dispose()。
Body 字段说明
messages必填数组（前端 user/assistant 历史）
model可选；否则 runtimeConfig.model
searchDocs=== true 时语义 C：prefetch 强制检索写 system；ReAct 不挂 searchDocs 工具

上游：前端取消「多 Agent」· 下游：createChatStream → runConversation；确认 → POST /api/chat/confirm

ConfirmSession 必须 per-request 创建并 finally dispose，否则 wait 泄漏。过程事件必须在流中途写出，不能等整段结束后再推 pending_confirm。
SSE 事件顺序（典型）
  1. injection_detected / degradation（可选，来自 createChatStream）
  2. tool_call / pending_confirm / confirm_resolved / tool_result …
  3. delta（最终文字，可多次）
  4. usage → [DONE]

chatMulti.ts · POST /api/chat/multi

registerChatMultiRoutes
export function registerChatMultiRoutes(app: Express): void
  1. SSE 头；校验 messages 非空且存在 user 内容；取最后一条 user作为本轮问句。
  2. AbortController + ConfirmSession + writeSse / onTrace 闭包。
  3. detectInjection(userText)：level≠none 时 SSE injection_detected（只标记不拦截）。
  4. UsageAccumulator；compileMultiAgentGraph({ accumulator, confirmSession, onTrace, writeSse, forceKbSearch: searchDocs===true })。
  5. graph.invoke({ userMessage, apiKey, baseUrl, model, signal, … })——过程中已写 supervisor_route / worker_done / 确认事件。
  6. invoke 结束后写 { delta: finalOutput }（整段，非逐字流式）。
  7. writeUsageToStream endpoint="chat/multi" → [DONE]；finally dispose。
Body 字段说明
messages非空；图只吃最后一条 user（history 暂不进 Supervisor）
model可选
searchDocs=== true → forceKbSearch：Supervisor 后若无 kb 则强制追加，由 kbWorker 调 searchDocs

上游：前端勾选「多 Agent」· 下游：multi-agent/graph；确认共用 chatConfirm

必须在 invoke 进行中写 SSE：actionWorker 可能 await ConfirmSession.wait；若整图结束后再推，前端永远收不到 pending_confirm。与单 Agent 防护语义对齐：input 本文件、tool 在 Worker、output 在 aggregate。
SSE 事件顺序
  1. injection_detected? → supervisor_route →（确认链）→ worker_done×N
  2. delta（Aggregate 后全文，已过 outputGuard）→ usage → [DONE]

registerChatConfirmRoutes
export function registerChatConfirmRoutes(app: Express): void
  1. 挂载 POST 与 GET 两条路径（见下）。
  2. 本文件不 new ConfirmSession，只 get + resolve。

上游：前端确认按钮 · 下游：getConfirmSession → session.resolve

会话由聊天请求创建并登记；confirm 路由若自行 new，会得到空 Map 项，永远对不上 wait。
POST /api/chat/confirm
(内部 handler) Body: { confirmId, toolCallId, action: "allow"|"deny" }
  1. 校验三字段类型与 action 枚举；失败 400。
  2. getConfirmSession(confirmId)；无会话 → 404。
  3. session.resolve(toolCallId, action)；无 pending → 404。
  4. 成功 JSON { ok, confirmId, toolCallId, action }。
字段说明
confirmIdSSE pending_confirm 带来的会话 id
toolCallId模型 tool_calls[].id
actionallow 后真正 run；deny 只回填错误

上游：UI · 下游：单 Agent applyToolCalls / 多 Agent runToolSafely 继续执行

成功只表示「解开了 wait」；真正 run 仍在原 SSE 请求栈帧内。
GET /api/chat/confirm/:confirmId
(内部 handler) → { confirmId, pending[] }
  1. 查 session；无则 404。
  2. 返回 listPending()（toolCallId / name / arguments）。

上游：curl 联调 · 下游：调试视图

学习 demo 便于排查「点了按钮却 404」；正式产品可不暴露。

registerRagChatRoutes
export function registerRagChatRoutes(app: Express): void
  1. setSseHeaders；校验 question 非空字符串。
  2. history 经 isRagHistoryItem 过滤；AbortController 绑 close。
  3. inputGuard：detectInjection → 可选 SSE injection_detected（不拦截）。
  4. UsageAccumulator + bindUsageCallback(..., "rag")。
  5. runAnswer：answerFromDocs(..., onTrace→writeSse) → 写 rag_meta（hits/empty/…）→ 写 {delta: answer}（整段；complete 非流式）。
  6. 若 LangSmith 开启：外裹 traceRagRequest。
  7. writeUsageToStream(..., "rag/chat") → [DONE]；取消时 error「已取消」。
Body 字段说明
question必填当前问句
history可选，仅 user/assistant
model可选

上游：前端「资料问答」· 下游：rag/answerFromDocs；Token / Guard / LangSmith

独立于 /api/chat：不进 ReAct、不挂天气工具。用 delta 复用前端气泡逻辑，但答案一次推送；hits 走 rag_meta，避免只靠拼字丢面板数据。注释里旧写「JSON」以现行 SSE 源码为准。
SSE 事件顺序
  1. injection_detected? → tool_call / tool_result（searchDocs）→ output_leak_blocked?
  2. rag_meta → delta(answer) → usage? → [DONE]
