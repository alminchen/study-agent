14 · Tools & MCP server/tools · server/mcp

工具「schema（给模型看）+ methods（本地执行）」分离；注册表粘合。 MCP 复用同一套 methods，不重写业务校验。

设计约定

  • arguments 进 run 仍是字符串（接口原样），各工具自己 JSON.parse。
  • 失败一律 { error: string }，不往外 throw——便于回填模型 / MCP isError。
  • 新增工具：新建 modules/<name>/index.ts → 自动进注册表；Guard 白名单 / MCP 注册 / 确认名单均从注册表派生，无需改别处。
聊天、多 Agent、MCP、Evals 共用同一 run，避免三套天气逻辑漂移。

tools/types.ts

ToolSchema

OpenAI 兼容 function 定义：name / description / parameters。只描述能力，不含执行。

ToolDefinition
{ name, schema, run(rawArguments) }

本地完整形状；由 index 粘合。

tools/index.ts

toolSchemasForChat(includeSearchDocs, includeConfirmTools?)
→ ToolSchema[]
参数默认行为
includeSearchDocs—false 时去掉 searchDocs
includeConfirmToolsfalsefalse 时去掉需确认工具（draft_message）
未建 ConfirmSession 时不应把 draft_message 暴露给模型；知识库开关与确认开关正交。
toolSchemas

全部 schema（含 draft_message）。一般不直接喂 /api/chat；调试 / 枚举用。

findTool(name)
→ ToolDefinition | undefined

按名取实现；需确认工具确认通过后仍走同一 find + run。

schemas/weather.ts · methods/weather.ts

getWeatherTool

description 约束：地球城市气温/天气；city 必填；不适用天体。

parseGetWeatherArgs(raw)
判别联合 ok/args | ok:false/error
executeGetWeather(args)
  1. isNotEarthCity（火星/月球等）→ error，不编造。
  2. 北京/上海预设；其它城市用字符 seed 稳定 mock。
不维护地球城市白名单，避免广州/杭州被误拦；天体黑名单即可。
runGetWeather(rawArguments)

parse → execute；统一入口给 findTool。

schemas/time.ts · methods/time.ts

getCurrentTimeTool

无参数（properties {}）；描述强制「问几点必须调工具，勿凭记忆」。

parseGetCurrentTimeArgs / executeGetCurrentTime / runGetCurrentTime

空串或 {} 合法；返回 iso / formatted(zh-CN) / timezone（本机 Intl）。

时间必须来自本机时钟，禁止模型瞎编「现在」。

schemas/searchDocs.ts · methods/searchDocs.ts

searchDocsTool

question 必填；不用于天气/时间。

parseSearchDocsArgs / executeSearchDocs / runSearchDocs
  1. 解析 question。
  2. retrieveForAnswer：判空则 error（含门槛话术）。
  3. 成功 → hits 视图（id/source/title/text/score），不含 embedding。
  4. catch：向量库空 → 提示先 rag:ingest；其它 → 检索服务异常。
分数门槛/重排仍在 rag/；工具层只做「变成 tool 结果」。三类失败话术区分系统问题 vs 无相关内容。

schemas/draftMessage.ts · methods/draftMessage.ts

draftMessageTool

to + body 必填；学习用假发送，不真外发。

不用 getWeather 加确认——只读工具加确认会破坏体验与回归；「起草消息」语义最贴近有后果。
parseDraftMessageArgs / executeDraftMessage / runDraftMessage

成功返回 { ok, simulated:true, to, body, message }；console 打模拟日志。deny 时上层根本不调用本文件。

mcp/createServer.ts

mcpFromRun(run, args)
内部 helper
  1. run(JSON.stringify(args ?? {}))。
  2. 包装 MCP content[{ type:text, text: JSON }]；对象含 error 则 isError。
createStep1McpServer()
→ McpServer

for (const t of toolsWithMcp()) registerTool(t.name, …)：工具集由注册表派生，描述复用 schemas，执行复用 methods。入参用 tool.mcp.inputSchema（zod shape，MCP 协议要这个，与给模型看的 JSON Schema 不是同一种格式），缺省补空 shape。不含 draft_message（mcp.expose: false，确认协议属聊天 SSE）。

SDK 用 registerTool 而非弃用的位置参数 tool()；业务校验不在 MCP 层重复；加工具不用改 MCP 代码。

mcp/stdio.ts

main()
  1. dotenv 加载 .env.local / .env。
  2. createStep1McpServer() + StdioServerTransport connect。
  3. 日志只打 stderr，避免弄脏 stdin/stdout 上的 JSON-RPC。
Cursor / Inspector spawn 本进程；与 Express HTTP 聊天并行存在。

接外部客户端

  • 客户端 spawn 本进程，用 command / args / cwd 三件套说清「跑什么、跑哪个脚本、在哪跑」。
  • cwd 必须指向项目根：stdio.ts 用相对路径读 .env / .env.local。
  • 对外工具 = toolsWithMcp() = getCurrentTime / getWeather / searchDocs。
