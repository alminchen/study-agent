单 Agent ReAct server/react/

LangGraph 调度的「问模型 ↔ 执行工具 → 回复」循环，外加人工确认闸门、知识库 prefetch、连续失败熔断。 HTTP 接线见 routes/chat.ts；入口拼装见 createChatStream（本页亦摘要）。

现网主路径
  1. createChatStream：clipMessages + inputGuard →（Mock 或）runConversation
  2. prefetchSearchDocsIfEnabled（勾选知识库时）；判空则直接 onDelta 固定文案
  3. LangGraph：START → askModel ⇄ applyTools → reply → END
  4. 需确认工具：pending_confirm → ConfirmSession.wait → POST confirm → allow/deny

runConversation.ts

compileReactGraph（内部）
function compileReactGraph(options, apiKey, failures): CompiledGraph
  1. 必须按请求现组：节点闭包本请求的 options/apiKey/failures，禁止模块级单例。
  2. 声明状态 Annotation：messages、turn、toolCalls、assistantContent、assistantReasoningContent、finalText。
  3. 节点 askModel：requestCompletion（可包 LangSmith chat-llm span；工具轮 thinking 默认 disabled）；无 tool_calls → finalText=文字；有工具且未到上限 → finalText=null + 保存 toolCalls；达 MAX_MODEL_TURNS=5 → 停止文案。
  4. 节点 applyTools：pushAssistantWithTools（含 reasoning_content）→ applyToolCalls → turn+1。
  5. 节点 reply：searchDocs 时 normalizeKnowledgeAnswer → detectLeakage → onDelta(safeText)。
  6. 边：START→askModel；条件边 ask→applyTools|reply；applyTools→askModel；reply→END。
参数说明
options本轮 ReactLoopOptions
apiKeyLLM Key
failures跨节点共用的连续失败计数器

applyToolCalls.ts

applyToolCalls
export async function applyToolCalls(toolCalls, messages, onTrace?, turn, failures, confirmSession?, signal?): Promise<void>
  1. 按数组顺序逐个处理（一轮可多工具，如天气+时间）。
  2. 解析 arguments JSON（失败仍展示原始串）→ onTrace tool_call。
  3. validateToolCall：拒绝 → {error}，不进确认/run。
  4. failures.isStopped → 回填 stoppedResult，不再 run。
  5. 需确认名 → runWithOptionalConfirm；否则 runToolCall（LangSmith 包一层）。
  6. failures.record；onTrace tool_result；push role:tool 消息。
参数说明
toolCalls本轮模型返回的调用列表
messages就地 push tool 回填
onTrace过程面板
turn当前询问轮次（日志/tracing）
failures连续失败跟踪器
confirmSession未传则需确认工具安全降级
signal打断 wait

上游：LangGraph applyTools · 下游：tools methods / confirmGate / 下一轮 askModel

失败一律变 {error} 不往外 throw，保证图能继续问模型改口。需确认但无 session → 绝不 run，防 draft_message 误执行。
runWithOptionalConfirm（内部）
async function runWithOptionalConfirm({ call, parsedArgs, turn, onTrace, confirmSession, signal })
  1. 无 session → { error: 未启用确认通道 }。
  2. onTrace pending_confirm(confirmId, toolCallId, name, args)。
  3. await confirmSession.wait；abort/dispose → 回填错误。
  4. onTrace confirm_resolved；deny → 用户拒绝错误；allow → runToolCall。

上游：applyToolCalls · 下游：前端 UI + POST confirm

从主循环拆出确认路径，避免 for 过长；拒绝与失败同形状，模型处理路径统一。

ConfirmSession.wait
wait(toolCallId, name, args, signal?): Promise<"allow"|"deny">
  1. 已 dispose / signal 已 abort → reject。
  2. new Promise，登记 pending（含 abort 监听清理）。
  3. resolve 时删 pending 并去掉 abort 监听。

ConfirmSession.resolve
resolve(toolCallId: string, action: ConfirmAction): boolean
  1. 查 pending；无则 false（id 错/已处理）。

export async function prefetchSearchDocsIfEnabled(messages, options, failures): Promise<PrefetchResult>
