RAG 管线 server/rag/

离线入库（切分 → 向量 → 落盘）与在线问答（召回 → 判空 → 重排 → 拼 prompt → 无 tools 补全）的完整实现。 HTTP 入口见 routes/ragChat.ts；本页只讲 server/rag/*。

在线主路径（有资料时）
  1. answerFromDocs：toolGuard(searchDocs) → retrieveForAnswer
  2. retrieve：load 库 → embed([question]) → LocalVectorStore.search（候选 K=20）
  3. judgeRetrieval：分数闸门 + 标题例外 → 空则固定文案、不调 LLM
  4. rerankHits（有模型）或向量 TopK 降级 → buildRagPrompt
  5. completeRagMessages → normalizeKnowledgeAnswer → detectLeakage

DocumentChunk
export interface DocumentChunk { id; source; title; text; seq }
  1. 切分产物：入库前每条必须带齐来源字段。
  2. id 形如 notes-chunk-3；seq 从 0 起。
  3. title 为所属 Markdown 标题；文首无标题时为空串。
字段类型含义
idstring稳定块 id
sourcestring文件名，如 stage3-rag-notes.md
titlestring所属标题
textstring块正文（常以标题开头）
seqnumber块序号

export interface ChunkOptions { maxChars?; overlapRatio? }

SearchHit
export interface SearchHit { chunk: StoredChunk; score: number; rerankScore?: number }
  1. score：向量余弦，召回排序用。
  2. rerankScore：交叉编码器 logit，重排后才有。

上游：search / rerankHits · 下游：判空、拼 prompt、面板 RagHitView

两套分数字段并存，面板可对照「向量名次 vs 重排名次」，教学价值高。
RetrievalJudgment
export interface RetrievalJudgment { empty; hits; rawHits; rankedAll; topScore; message? }
  1. empty=true 不代表 search 没返回行：rawHits 仍是原始 TopK。
  2. hits 才是允许注入 prompt 的列表；判空时为空。
  3. 分数低于门槛但 Top1 标题对上问句时，empty 仍可为 false（见 retrieve）。
字段含义
empty能否当资料用
hits注入 prompt 的块（重排后 TopK 或降级切片）
rawHits向量召回候选（未重排），判空后仍保留
rankedAll按重排分排好的全列表；判空/未重排时可能为空
topScoreTop1 向量分；无命中为 null
message空结果固定文案

上游：judgeRetrieval / retrieveForAnswer · 下游：buildRagPrompt、toPublicHits

「有名次 ≠ 有资料」必须在类型层拆开，否则低分噪声会进 prompt，模型容易瞎编。

chunker.ts

chunkMarkdown
export function chunkMarkdown(markdown: string, source: string, options?: ChunkOptions): DocumentChunk[]
  1. 解析 maxChars / overlapRatio，算 overlapChars。
  2. splitByHeadings：按行首 #/##/### 分成节（更深标题当正文）。
  3. 节内 splitParagraphs（空行边界），用 buffer 攒相邻小段，尽量不超过 maxChars。
  4. 拼上会超：先 flush 已攒内容；单段仍超则 splitLongText（滑动窗口 + 句界 + overlap）。
  5. isJunk 丢掉过短/目录/页码块；withTitlePrefix 把标题带到块首。
  6. 用文件名 stem 生成 {stem}-chunk-{seq} 并返回。
参数类型说明
markdownstring全文 Markdown
sourcestring来源文件名（写入每块 source）
optionsChunkOptions可选覆盖默认 400 / 0.15

上游：ingest 脚本读 md · 下游：embed → replaceSource 入库

先保结构（标题）再保意思（段落拼凑）最后保接缝（overlap）：宁可块稍小，也不要一段混多个主题；overlap 避免关键句刚好落在缝上两边都搜不到。

内部辅助（未 export，但理解切分必读）：

  • splitByHeadings — 只认 h1～h3；碰新标题先 push 上一节；循环后再 push 一次防丢末节。
  • splitLongText — 窗口内找最后的换行/「。」/「；」；断点太靠前则硬切；下一块 start = end − overlap。
  • isJunk — 压空白后 <8 字、纯「目录」、纯「第 N 页」丢弃，防污染检索。

embed
export async function embed(texts: string[]): Promise<number[][]>
  1. 空数组直接返回 []。
  2. 懒加载 pipeline("feature-extraction", MODEL_DIR)：local_files_only + dtype: "q8"。
  3. 调用 ext(texts, { pooling: "mean", normalize: true })。
  4. tolist() 得到行向量；逐行检查长度 === EMBED_DIM。
参数类型说明
textsstring[]一批待编码文本（入库多块或问句单条）

上游：ingest / retrieve · 下游：StoredChunk.embedding / store.search(queryVec)

问句与入库必须走同一个 embed；漏掉 mean pooling 或 normalize 会直接搜不准。本地模型目录避免运行时拉网。
cosine
export function cosine(a: number[], b: number[]): number
  1. 在共同前缀长度上累加点积与各自范数平方。
  2. 返回 dot / (‖a‖‖b‖)；分母为 0 时用 1 避免 NaN。
参数类型说明
a / bnumber[]两向量；长度取 min

上游：自测 / LocalVectorStore.search · 下游：按分排序 TopK

归一化后余弦等价于点积，但自测「同句应接近 1」时显式余弦更直观。

retrieve.ts

DEFAULT_TOP_K / MIN_TOP_SCORE / CANDIDATE_K
export const DEFAULT_TOP_K = 5 · MIN_TOP_SCORE = 0.6 · CANDIDATE_K = 20
  1. 注入默认 5：Top1 易漏，Top20 太吵。
  2. 0.6 挡无关问题（如天气问资料库 Top1≈0.28）。

retrieve
export async function retrieve(question: string, topK = DEFAULT_TOP_K): Promise<SearchHit[]>
  1. new LocalVectorStore() → load()。
  2. size===0 → 抛「请先 npm run rag:ingest」。
  3. embed([question]) 取 queryVec。
  4. store.search(queryVec, topK) 返回原始命中（不做空判断）。
参数说明
question用户问句
topK召回条数（retrieveForAnswer 传 CANDIDATE_K）

上游：问答编排 · 下游：judgeRetrieval；尚不调聊天模型

返回非空只表示「排得出名次」。有没有资料交给 judge / retrieveForAnswer。
judgeRetrieval
export function judgeRetrieval(rawHits, minTopScore = MIN_TOP_SCORE, question = ""): RetrievalJudgment
  1. 取 Top1 的 score；算 headingMatchesQuestion(title, question)。
  2. 无命中 / topScore null /（分 < 门槛且标题不对）→ empty：hits=[]，保留 rawHits，message 固定文案。
  3. 否则 empty=false，hits=rawHits（此时尚未重排切片）。
参数说明
rawHits向量召回列表
minTopScore默认 0.6
question用于标题点名例外

上游：retrieve · 下游：retrieveForAnswer / buildRagPrompt

实测「不要在这个阶段做的事」命中正确块但分≈0.5571；只看 0.6 会误杀。短标题对长块余弦偏低是正常现象，标题互相包含则放行。
retrieveForAnswer
export async function retrieveForAnswer(question, topK = DEFAULT_TOP_K, minTopScore = MIN_TOP_SCORE): Promise<RetrievalJudgment>
  1. retrieve(question, CANDIDATE_K) 宽召回。
  2. judgeRetrieval；若 empty 直接返回。
  3. 若 !rerankerReady()：warn，hits = rawHits.slice(0, topK)，rankedAll=[]。
  4. 否则 rerankHits → hits=injected，rankedAll 填满。
参数说明
question问句
topK最终注入条数
minTopScore闸门阈值

上游：answerFromDocs / searchDocs 工具 · 下游：buildRagPrompt

问答/拼 prompt 应走这一层：召回 + 闸门 + 重排打包，避免调用方漏步骤。

rerankHits
export async function rerankHits(question, candidates, keep): Promise<{ injected; rankedAll }>
  1. 候选为空 → 双空数组。
  2. 懒加载 tokenizer + AutoModelForSequenceClassification（local、q8）。
  3. 对每条：tok(question, { text_pair: chunk.text, truncation, max_length: 512 }) → 模型 → 读 logit。
  4. 保留原向量 score，写入 rerankScore；按 rerankScore 降序。
  5. injected = ranked.slice(0, keep)，rankedAll = ranked。
参数说明
question问句（交叉编码器一侧）
candidates向量召回候选
keep注入条数

上游：retrieveForAnswer · 下游：prompt 注入列表 / 面板排名

双塔召回宽、交叉编码器精排窄：先 20 再留 5，精度与上下文长度兼顾。score 保留便于面板对比。

answerFromDocs
export async function answerFromDocs(question, history=[], signal?, model?, onUsage?, onTrace?): Promise<RagAnswer>
  1. trim question；构造假想 tool 参数 { question }。
  2. onTrace tool_call(searchDocs) → validateToolCall；拒绝则 tool_result.error，返回 toolGuardBlocked，不检索。
  3. runRagRetrieveWithTracing → retrieveForAnswer；再 tool_result 摘要 empty/topScore/hitCount。
  4. buildRagPrompt；toPublicHits；若 prompt.empty → 固定文案，calledModel=false。
  5. runRagLlmWithTracing → completeRagMessages。
  6. normalizeKnowledgeAnswer → detectLeakage；泄露则 onTrace output_leak_blocked，answer=safeText。
参数说明
question当前问句
history此前 user/assistant（不含当前问、不含 system）
signalAbortSignal
model可选模型名
onUsageToken
onTrace过程事件 → SSE
