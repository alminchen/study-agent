server/index.ts

进程入口（无 export，直接执行）
dotenv → express() → express.json → registerRoutes(app) → app.listen(PORT, HOST)

做什么

  1. 先 dotenv.config(".env.local") 再 .env：本机密钥优先，后者不覆盖已有值。
  2. express.json({ limit: "1mb" })：限制聊天 body 体积，防超大 history。
  3. 调用 registerRoutes(app) 挂上全部 API（本文件不写具体 path）。
  4. listen 后打印 mode（mock/api）与是否有 Key；无 Key 时 warn，仍可起服跑 Mock。
上下游：npm run dev:server → 本文件 → routes/index → 各端点
入口只做接线，找「哪个 URL 干什么」去 routes/；避免 index.ts 膨胀成上帝文件。

server/runtimeConfig.ts

getRuntimeConfig
getRuntimeConfig(): { apiKey, forceMock, mockMode, model, baseUrl }

做什么

  1. 读 LLM_API_KEY（trim）；空串视为无 Key。
  2. forceMock = MOCK_MODE===\"1\"；mockMode = forceMock || !apiKey。
  3. 返回默认 model（LLM_MODEL 或 deepseek-chat）与 baseUrl。
字段含义
mockMode路由层可据此决定是否走假流 / 健康检查文案
forceMock即便有 Key 也强制 Mock（教学/演示）
上游：index 启动日志、chat/multi/rag/health 路由 · 下游：无，只读 env
所有 handler 共用一处读配置，避免「某处忘了判 MOCK」导致半真半假。

server/chat.ts

buildSystemPrompt（内部）
buildSystemPrompt(searchDocs: boolean): string

做什么

  1. 基座 SYSTEM_PROMPT：何时必须调 getWeather / getCurrentTime / draft_message。
  2. 按本轮 searchDocs 追加 KB_ON 或 KB_OFF 文案（强调「开关只对本轮生效」）。
  3. 末尾拼 SYSTEM_PROMPT_GUARD 防注入边界。
把「工具规则 / 知识库口吻 / 安全」三段拼接，比前端塞 system 更可控；KB 文案按轮切换，避免历史勾选污染本轮。
createChatStream
async createChatStream(options: CreateChatStreamOptions): Promise<void>

做什么

  1. 解析 apiKey / forceMock / searchDocs；拼 system（可被 options.systemPrompt 覆盖）。
  2. clipMessages：截最近 N 条 + 注入 system。
  3. 对最后一条 user 做 detectInjection：只 onTrace(injection_detected)，不拦截。
  4. 无 Key 或 forceMock → onTrace(degradation) → streamMock 后 return。
  5. 否则 runConversation(…, apiKey) 进入 ReAct（含 confirmSession / onUsage）。
入参要点说明
messages前端 user/assistant；不含可信 system
searchDocs本轮是否强制检索 + 挂 searchDocs 工具
confirmSession有则需确认工具会 await wait
onDelta / onTrace / onUsage由路由接到 SSE
上游：routes/chat.ts · 下游：clipMessages → inputGuard → streamMock | runConversation
路由只管 HTTP/SSE；门面集中「裁剪 + 降级 + 进图」。资料问答故意不走这里，避免聊天工具 system 污染 RAG。

server/clipMessages.ts

clipMessages
clipMessages(messages, systemPrompt, maxContextMessages): TextMessage[]

做什么

  1. messages.slice(-max) 只留最近若干条（至少 1）。
  2. 返回 [{role:system, content:systemPrompt}, ...recent]。
成本与注意力：整段历史塞满会烧 Token；system 永远服务端注入，前端无法伪造规则。

server/mock/streamMock.ts

streamMock
async streamMock({ messages, signal, onDelta }): Promise<void>

做什么

  1. 取最后一条 user 文本，拼一段说明「当前 Mock」的回复。
  2. 按 4 字切块，循环 onDelta + sleep(24ms) 模拟打字。
  3. 若 signal.aborted 则抛 AbortError，与真流式取消对齐。
无 Key 时前端仍能跑通 fetch+ReadableStream；不计 Token（外层 Accumulator 保持 empty）。

server/answer-style/knowledgeAnswer.ts

normalizeKnowledgeAnswer
normalizeKnowledgeAnswer(raw: string): string

做什么

  1. 删尾部「来源:」清单块。
  2. 删含 id=/source=/title= 的内部元信息行。
  3. 再兜底过滤 [n] id=... source=... 整行。
  4. 连续空行压成最多两个；trim。
上游：RAG answerFromDocs、聊天知识库回答出口 · 下游：通常再接 detectLeakage
保留行内 [1][2]，去掉「检索结果打印感」；在 outputGuard 前清理，减少格式噪音误触指纹。
