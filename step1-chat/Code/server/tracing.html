13 · Tracing server/tracing/langsmith.ts

LangSmith 开发者观测层：用 traceable() 手动打 span。 不是给终端用户看的——页面过程面板仍走 SSE onTrace → ToolTracePanel。

为何要单独适配层

LLM 调用在 react/complete.ts 是手写 fetch（DeepSeek 兼容 + thinking 的 reasoning_content）， 没有走 @langchain/openai ChatModel，因此 LangChainTracer 不会自动包住每次 HTTP。 本文件在关键节点手动打 span，与 LangGraph 节点对齐。

观测是调用方责任：methods/MCP 保持可共用；不把 LangSmith 写死进 tools/methods。
环境变量作用
LANGCHAIN_TRACING_V2=true（或 LANGSMITH_* 等价）总开关；关则函数仍可调但不上报
LANGCHAIN_API_KEY进哪个 Workspace
LANGCHAIN_PROJECTtrace 分组名（非 Workspace 名；不存在会自动创建）

Span 树（单 Agent 示例）

chat-request (chain) ← runConversation 整次 invoke
├─ chat-prefetch? (tool) 勾选搜索知识库时（语义 C）
├─ chat-llm (llm) turn=1 可能出 getWeather（span 名刻意 ≠ 节点 askModel）
├─ tool (tool) tool_name=getWeather
├─ chat-llm turn=2 …
└─ chat-llm turn=N 无 tool_calls → reply
multi：multi-request → multi-supervisor / multi-workers / multi-aggregate + multi-llm / tool
RAG：rag-request (chain) → rag-retrieve (tool) → rag-llm (llm)
故意截断：messages 全文、API Key、工具结果 >500 字、用户问句 >120 字——防泄密与噪声。

导出一览

isLangSmithTracingEnabled()
→ boolean

检查 LANGCHAIN_TRACING_V2 / LANGSMITH_TRACING_V2 / LANGCHAIN_TRACING / LANGSMITH_TRACING 任一为 "true"。

WHERE：runConversation.ts 决定 askModel 走 traceAskModel（span chat-llm）还是直调；prefetch 走 runPrefetchWithTracing；runToolWithTracing / RAG / multi 包装器同理。
与 @langchain/core 开关语义对齐，避免只认一个变量名。
traceChatRequest
traceable · name "chat-request" · run_type chain
入参说明
run() => Promise<void> 闭包，内部仍是 graph.invoke
userPreview列表里认问句；processInputs 截到 120 字
  1. runConversation 最外层：若 tracing 开，用本函数包整段 ReAct。
  2. 内部 run 执行原来的 compile + invoke，不改业务。
WHERE：server/react/runConversation.ts
traceAskModel
traceable · name "chat-llm" · llm（函数名仍叫 traceAskModel）
入参说明
turn当前轮次
messages仅记 message_count，不上报全文
options记 model、search_docs_prefetch
apiKey传给 requestCompletion，不上报

内部 requestCompletion(..., { disableThinking: true })；processOutputs 暴露 finish_reason、has_tool_calls、tool_names。

WHERE：runConversation 的 askModel 节点
span 名不用 askModel，避免与 LangGraph 节点同名叠两层；排错先看 has_tool_calls / tool_names。
runPrefetchWithTracing / traceChatPrefetch
traceable · "chat-prefetch" · tool

语义 C：勾选搜索时服务端强制检索的独立 span（candidate_k、hit_count）。

WHERE：prefetchSearchDocs.ts
traceToolRun
traceable · "tool" · tool

包装单次 tool 执行；inputs 解析 arguments；outputs 标 is_error + result_preview(500)。

WHERE：仅经 runToolWithTracing 间接使用
runToolWithTracing(turn, call)
→ Promise<unknown>
  1. findTool；未知 → { error }。
  2. tracing 关：直接 tool.run，catch → { error }。
  3. tracing 开：traceToolRun({ turn, call, run })，同样不往外 throw。
WHERE：react/applyToolCalls.ts（单 Agent）与 multi-agent/runToolSafely.ts（allow 之后）。
异常变 { error } 回填模型，与阶段 4 工具失败策略一致；methods 层保持干净。
lastUserPreview(messages)
→ string

从末尾找最后一条 user content，供 chat-request 的 user_preview。

WHERE：runConversation 包 traceChatRequest 时
traceRagRequest
traceable · "rag-request" · chain

与 chat-request 并列的根 span；内部再挂 retrieve + rag-llm。

WHERE：routes/ragChat.ts 包 answerFromDocs 整段
traceRagRetrieve / runRagRetrieveWithTracing
tool span · 开关包装

观测向量检索（语义对齐 searchDocs）；outputs：empty / top_score / hit_count。调用前业务侧已过 validateToolCall。

WHERE：rag/answer.ts（经 runRagRetrieveWithTracing）
traceRagLlm / runRagLlmWithTracing
llm span · 开关包装

包 completeRagMessages（无 tools）；记 model、message_count、content_preview、has_usage。

WHERE：rag/answer.ts

与 SSE Trace 的边界

SSE onTraceLangSmith
受众终端用户 / 产品面板开发者
开关始终随请求推环境变量，默认关
确认闸门pending_confirm 必需不参与交互
multi全套过程 + route/done独立 multi-request 树（supervisor / workers / aggregate）；勾选搜索 → forceKbSearch
混成一套会导致：要么把开发细节推给用户，要么关 LangSmith 后面板也没了。
